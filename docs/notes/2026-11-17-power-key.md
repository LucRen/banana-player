# The power key with the lid shut: play/pause, and a hold to sleep

**Asked:** with the lid shut and "When the lid closes: Keep playing", the power key should play/pause what is loaded
(with the panels dark, it is the only key at hand) and still be able to sleep the handheld.

## What BananaOS does

bananad reads the power key itself: an evdev device named `rk805 pwrkey` in `/dev/input/event*` (found by `EVIOCGNAME`,
never by number), with no setting of its own for it. It keeps the device open; the player can take it only with
`EVIOCGRAB` (an exclusive grab: bananad's reads then block and it gets no events). The kernel drops a grab when its fd
closes, so a crash or a quit gives the key back without any clean-up. A sleep is asked for as closing the lid with
`lid_sleep` on does: create `/run/banana/sleep-now`, then SIGHUP bananad (the same pair the lid code uses; now
`bp::askBananadSleep()` in `lidsleep_host.*`). A held fd would also hide the key from bananad while the handheld is
asleep, and that key is how it wakes, so the grab must be gone before the sleep.

## Design

- `src/powerkey.*`: `bp::PowerKey`, Linux only (elsewhere `start()` returns false and nothing runs, a Mac stub).
  `start(event)` makes a pipe and a thread; the thread owns the fd.
- Main calls `tick(want, why)` every pass of its loop: `want` is the setting **and** `SleepWatch::lidClosed()` **and**
  `player.playing()` (loaded: playing or paused; a stopped player, a video's end with nothing next, has `playing()`
  false; a song's list ending keeps its last song loaded, paused, so it counts). The tick stores `want` and a
  `CLOCK_MONOTONIC` beat. `why` is the reason the conditions are not
  met, used only when releasing a held grab ("Keep playing is off", "the lid opened", "nothing is loaded").
- With `want` true and the beat younger than 3 s, the thread finds the device by name, opens it
  (`O_RDONLY|O_NONBLOCK|O_CLOEXEC`) and grabs it: `power: /dev/input/eventN taken: lid shut, Keep playing, something
  loaded…`. A missing device, an open failure (errno) or a refused grab is logged once per stretch and not retried
  until the conditions end; `EBUSY` says bananad holds it exclusively and the feature stays off quietly.
- Its `EV_KEY`/`KEY_POWER` events: down notes the time. Released before 2 s: an SDL user event (`evPower` in
  `main.cpp`, `evMpv + 12`; `SDL_RegisterEvents` raised to 13). Main toggles through the Session as the pause button
  does: `SessionHost::play(player.paused)` then `Player::togglePause()` (a page that is the output is taken over as A
  does), and logs `power: press: play/pause`. `KEY_POWER` autorepeat is ignored; the 2 s is timed on the thread, and a
  release that arrives at or after 2 s still counts as a hold (its release can be read in the same poll as the
  deadline).
- Hold at 2 s: the grab is released first (`power: released (the 2 s hold: the sleep asked for)`), then
  `askBananadSleep()` (logged `power: hold: asking bananad to sleep`). The thread stays off until it wakes: a sleep
  stops the whole process group, so a gap of over 1 s in the thread's own clock and in main's beat (a stall of this
  thread alone leaves main's fresh) means it is back, and the key is taken again. It never re-grabs before the sleep:
  a held fd would keep bananad from seeing the key that wakes the handheld.
- Safety releases: `want` false (lid open, Stop, a video's end with nothing next, the setting off) within a poll (100 ms);
  the beat older than 3 s (`the player stopped answering`) even if `want` is still true, and no re-grab until it is
  fresh again; `stop()` at quit (`the player quits`); a read failure (`the device went away`). Closing the fd drops
  the grab in every case.
- The thread never touches the Player or the Ui: one SDL user event for a press, and the sleep ask (a file and a
  signal). `main.cpp` starts it after `SleepWatch`, ticks it at the top of the loop and stops it at quitting.

## Tested

- Desktop build (`cmake`, AppleClang) and `./build/core-test`: all passed. No pure helper was added, so no new core
  test.
- Mac: the stub compiles (the thread and evdev code are behind `__linux__`).
- arm64 Docker (`debian:trixie`, `-Wall -Wextra`, DEVELOPMENT.md's Linux check): `powerkey.cpp`, `lidsleep_host.cpp`
  and `main.cpp` compile with no warning of their own, and `/tmp/b/core-test` ends `core: all passed`.

## Not tested on the handheld

The real `rk805 pwrkey` name and grab (whether bananad holds it exclusively: `EBUSY` would leave the feature off), the
power key's events and their timings (`KEY_POWER` down/up), a hold's `sleep-now` + SIGHUP with the lid shut and the
wake key afterwards, and the release at lid open / Stop / the end of a list seen on the device. Worth checking first:
lid shut, Keep playing, a song playing (`log.txt` should show `power: … taken`), a short press (pause, `power: press:
play/pause`), a 2 s hold (sleep; `power: released (the 2 s hold…`), the power key waking it, then opening the lid and
closing it again (a fresh grab) and pressing power once more.
