# Themes: how the swap works

The spec is docs/redesign/components.md, Themes (values: docs/redesign/themes.py, the source of truth). This note is
what the code does with it.

- **One table.** `src/theme.cpp`: one line of base roles per theme, in the stepper's order. RAIL (SURFACE at 60% over
  BG unless the line names one), the TOP_* tokens (the theme's own, or another's: Light takes Yellow's, 16-bit Dark
  purple's, 32-bit Dark's) and Match theme's page come from the line. A new theme is a new line; the setting's ids and
  names (`themeIds()`, `themeNames()`) and the dashboard's CSS (`themeCss()`) are read from the table.
- **Names read the current theme.** `theme::BG` and the rest are references into `theme::current`, so every
  `using namespace theme` file (player.cpp, levelcard.cpp) and every `theme::X` reads the theme drawn now. Ui's SDL
  copies (`ui_internal.h`: `BG`, `TEXT`...) are references into `ink`, copied by `syncInk()`. Radii and strengths stay
  constexpr. `edgeOf(c)` reads EDGE_MIX; the 3-argument form is the table's own (themeCss, tests).
- **The swap** is main's loop: `shown().settings.theme != theme::currentTheme()` → `setTheme`, `Ui::themeChanged()`
  (ink, the PIN digits' textures, the support QR), `Player::themeChanged()` (the idle title and a song's lines sent to
  mpv again), both panels redrawn for 2 s (as after a wake). The theme is in `Ui::signature()`; the "Playing in your
  browser" card's key has it too. Log lines: `theme: A -> B`, `theme: bottom panel recoloured, N cached textures
  dropped`, `theme: top panel overlays sent again: N`.
- **Kept dark on purpose:** the top panel with nothing playing is mpv's black with the idle logo in TOP_ tokens (the
  spec wanted the main tokens there, so Light's top screen light: that needs mpv's background colour changed while
  idle; not done). The level card has no TOP_EDGE edge and the 100 mark stays TOP_TEXT, so Yellow is unchanged. The
  manga strip's not-yet-decoded grey (pagerender.cpp, a GL texture) is TOP_TRACK of the theme at start.
- **Dashboard:** `/theme.css` (server.cpp, from `themeCss()`): `:root[data-theme=ID]` blocks; style.css's `:root` is
  Yellow as before. The state carries `theme` and `themeBg`; js/events.js `applyTheme` sets data-theme and
  `theme-color` and keeps them in localStorage for the next load (index.html's inline script). `POST /api/setting
  key=theme value=ID` sets the handheld's (the page has no Theme row yet).
- **Checked:** core-test (`testThemes`: Yellow's values, the spec's worked-out colours for Light and Dark, ids
  round-trip, Match theme, themeCss); scripted shots of Yellow, Light, Midnight blue, 16-bit; a live swap with a song
  playing (log lines, the bottom shot); the dashboard in Light in headless Chrome. Not on the handheld: KMSDRM's
  redraw after a swap, and the colours on the real panels.
